# card-guess-bot

一个运行在 QQ 群和私聊里的《杀戮尖塔 1 / 杀戮尖塔 2》查询与互动机器人，通过 OneBot WebSocket 连接 NapCat。

它最初只是一个猜卡小游戏，现在也可以查卡牌、遗物和事件，查看本地统计快照，或在群里随机抽取事件并回复数字参与。它不是完整的《杀戮尖塔》模拟器，重点是用尽量短的 QQ 命令提供实用资料和轻量互动。

## 功能概览

- 查询 STS1 / STS2 卡牌，发送本地卡面；同名内容可用 `1` / `2` 指定代际。
- 查询 STS1 / STS2 遗物，显示效果、类型、本地图片以及当前可用统计。
- 直接按官方简体中文名查询 STS1 / STS2 Event，查看正文、选项、固定奖励和统计。
- 发送 `事件1` 或 `事件2` 随机开始一代或二代事件，群友回复选项数字即可参与。
- 部分经过验证的多阶段 Event 支持连续互动；复杂且尚未验证的流程仍可作为资料查询。
- Event 与固定 Card / Relic 之间有双向关联：查 Event 可看到固定奖励与简略效果，查相关卡牌或遗物可看到“事件关联”。
- 提供猜卡、卡牌选择率排行、STS1 Boss 遗物排行和 STS2 Ancient 遗物排行等短命令。

## 快速使用

群聊中先 `@机器人`，私聊可直接发送命令。

```text
白噪声1          # 查询 STS1 卡牌
白噪声2          # 查询 STS2 同名卡牌
赤牛2            # 查询 STS2 遗物及可用统计
大鱼             # 查询 STS1 Event 及统计
泉水             # 查询 STS2 Event 及统计
事件1            # 随机开始一个可互动的 STS1 Event
事件2            # 随机开始一个可互动的 STS2 Event
1                # 在随机事件中选择第 1 项
开始2 骨妹       # 开始 STS2 死灵契约师卡池猜卡
结束             # 结束当前互动事件或猜卡
帮助             # 查看 QQ 内帮助
```

查询使用精确名称，不支持拼音或模糊匹配。若两代都有同名内容，机器人会提示在名字后加 `1` 或 `2`。若同一个名字同时属于不同实体，可使用类型前缀消歧，例如：

```text
遗物 金神像1
事件 金神像1
卡牌 J.A.X.1
```

## 代表性 QQ 命令

| 想做什么 | 命令示例 | 当前行为 |
| --- | --- | --- |
| 查卡牌 | `残杀1`、`白噪声2` | 返回代际、角色、本地卡面和可用统计；有升级卡面时一并发送 |
| 查遗物 | `赤牛1`、`赤牛2`、`添水2` | 返回效果、类型、本地图片和对应统计 |
| 查 Event | `大鱼`、`泉水`、`满屋芝士` | 返回事件资料；直接查询不会开启互动会话 |
| 随机 Event | `事件`、`事件1`、`事件2` | 从当前支持互动的池中随机抽取；`事件` 会先随机代际 |
| 猜卡 | `开始`、`开始1 无色`、`开始2 骨妹` | 开始混合、一代或二代题库，可按角色或卡池限制 |
| 结束会话 | `结束` | 结束当前事件互动或猜卡 |
| 卡牌排行 | `观者1普通` | 查询 STS1 同角色、同层、同稀有度卡牌选择率排行 |
| Boss 遗物排行 | `Boss1`、`Boss2` | 查询 STS1 第一层或第二层 Boss 遗物选择率排行 |
| Ancient 遗物排行 | `达弗2`、`涅奥` | 查询 STS2 同一先古遗民、同层的选择率排行 |
| 先古遗民索引 | `先古遗民` | 查看可查询的先古遗民名称与本地总览图 |
| 帮助 | `帮助 查询`、`帮助 猜卡`、`帮助 排行` | 查看分项帮助 |

上面排行榜命令中的数字表示第几层。`Boss3` 当前只会提示没有第三层排行数据；STS2 卡牌暂不提供对应的角色分层排行榜。

## Card / Relic / Event 查询

### Card

卡牌查询覆盖 STS1 与 STS2。机器人会优先发送本地卡面，因此费用、类型、稀有度、效果和升级变化可以直接从卡图查看；本地存在升级卡面时会同时发送。

当前卡牌统计按数据可用性显示：

- STS1：各层卡牌奖励选择率、同角色同稀有度排名、胜率关联、首次选择层数和再次遇到时的选择情况。
- STS2：各层卡牌奖励选择、商店购买、休息处升级、胜率关联和样本量。

统计缺失或样本不满足展示条件时，相关行会隐藏，不会用 `0` 冒充未知数据。

### Relic

遗物查询覆盖 STS1 与 STS2，显示官方简体中文名、效果、类型和本地图片。当前玩家可见统计包括：

- STS1 Boss 遗物：按第一层、第二层分别显示真实选择率及同场景排名。
- STS1 普通、罕见、稀有遗物：数据可靠时显示首次获得区间和各角色最终携带情况。
- STS2 Ancient 遗物：按先古遗民与层数显示 offer → pick 的选择率及排名。
- STS2 可在商店购买的遗物：数据存在时显示各层购买比例、胜率关联和 offer 样本量。

遗物并非都拥有同一种统计；机器人只展示当前有合理比较场景和有效口径的数据。

### Event

直接发送事件官方简体中文名即可查询资料，例如 `大鱼`、`增益研究者`、`泉水`、`满屋芝士`。查询页可能包含：

- 事件正文、所在层或共享事件标记；
- 当前可见选项与效果；
- STS1 / STS2 Event Stats；
- 固定卡牌或遗物奖励及其简略效果；
- 已验证的后续分支，或后续数据仍不完整的明确提示。

直接查询是资料页，不会创建互动会话。随机 Event 才会等待群友回复数字。

## STS1 / STS2 统计能力

机器人运行时只读取仓库中的本地统计快照，不会为一次 QQ 查询扫描原始公开 run dump，也不依赖统计网站实时在线。

卡牌、遗物和 Event 使用的统计场景不同，不能把所有百分比理解成同一种“胜率”或“选择率”：

- STS1 卡牌选择数据来自卡牌奖励中的 offer → pick；胜率变化描述为历史关联，不代表拿到某张牌会导致胜率上升或下降。
- STS1 Boss 遗物使用 `boss_relics` 奖励记录；普通遗物的首次获得信息只在记录覆盖足够时显示。
- STS2 卡牌与商店遗物使用快照中已有的奖励、购买或升级场景；缺少有效 offer 分母时不会凭空计算选择率。
- STS2 Ancient 遗物只在同一先古遗民、同一层的真实选择场景内比较。

### Event Stats 口径

STS1 Event 显示“选项占比”“历史通关率”和样本量。其中“选项占比”是记录到的该选项决策数占该事件遭遇决策数的比例；原始 run 数据没有完整记录每次实际展示了哪些选项，因此它不是严格的 offer-based 选择率。

STS2 Event 显示“选项出现占比”“历史通关率”和样本量。“选项出现占比”以 Event encounter 为基础；对于可以反复选择同一选项的事件，同一次遭遇会贡献多次记录，所以占比可能超过 100%。

两代 Event 的“历史通关率”都只是选择该选项的历史对局与通关结果之间的关联，不代表因果，也不是路线推荐。QQ 输出使用简短提示：

```text
※ 历史统计，仅代表关联，不代表因果。
```

## Event 随机互动

- `事件1`：随机抽取一个当前可完整处理的 STS1 Event。
- `事件2`：随机抽取一个当前可完整处理的 STS2 Event。
- `事件`：先在 STS1 / STS2 中随机选择一代，再从对应互动池抽取。
- 事件开始后回复可见选项的数字；群聊中第一个有效回答者结算该选项。
- 非法数字不会推进事件；发送 `结束` 可随时结束互动。

大多数当前支持的互动是“一次选择后结束”。目前 `滑脚木桥` 与 `深渊浴场`这两个经过验证的多阶段事件支持连续选择。其他复杂流程仍可按名称查询资料，但不会进入随机互动池。

## Event ↔ Card / Relic 双向关联

关联来自经过核对的本地固定映射，并不覆盖所有卡牌、遗物与事件。

- 查 Event：例如 `增益研究者` 会标出固定获得的 `J.A.X.`、`突变之力`及条件替代奖励；`满屋芝士`会标出固定遗物`天选芝士`和简略效果。
- 查 Card / Relic：例如 `J.A.X.1`、`头环1`或`遗物 金神像1`会追加“事件关联”，说明它在哪个事件中获得、替代或被献上。
- “随机卡牌”“随机遗物”不会被伪装成某个固定实体，也不会生成虚假的反向关联。

## 数据来源与本地快照

- 卡牌与遗物目录：维护脚本从 Spire Archive 的 STS1 / STS2 API 下载简体中文目录；遗物同时合并英文名称用于稳定匹配。
- Event 目录：仓库包含经过整理的 STS1 / STS2 本地事件快照；STS2 中文文本以审计过的简体中文本地化数据为主，并结合 Spire Archive 的结构数据。
- STS1 卡牌、遗物和 Event Stats：来自 Mega Crit 公开的 2020 年 11 月约 12 万局样本。卡牌与 Event 的当前统计队列主要筛选进阶 7～20；遗物快照有独立的记录与展示口径。
- STS2 卡牌、遗物及 Ancient 统计：使用仓库内由 Untapped 与 Spire Codex 数据生成的快照，各指标只在其对应的奖励、商店或 Ancient 选择场景中解释。
- STS2 Event Stats：由 `sts2runs.com` 的公开 run dump 离线聚合，当前快照筛选标准模式、进阶 7+，排除作弊与放弃对局并保留失败对局。

原始大体积 run dump 不需要随 Bot 部署，也不会在 QQ 查询时读取。统计快照记录的是历史数据切片，可能落后于当前游戏版本。

## 安装与运行

### 1. 准备 Python 环境

代码使用 Python 3.10+ 语法。仓库目前没有依赖锁文件；QQ runtime 的直接第三方依赖为 `jieba` 和 `websockets`，下载卡牌/遗物目录的维护脚本还需要 `requests`。

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install jieba websockets requests
```

### 2. 准备本地目录与图片

Event 目录和统计快照已提交到仓库。卡牌、遗物原始目录和全部图片属于本地资产，不由 Git 跟踪。首次部署至少需要生成以下目录文件：

```powershell
python scripts\download_cards.py
python scripts\download_relics.py
```

它们会写入：

```text
data/raw/sts1_cards.json
data/raw/sts2_cards.json
data/raw/sts1_relics.json
data/raw/sts2_relics.json
```

QQ runtime 不会临时联网补图，只会读取 `data/images/` 中已经准备好的 PNG。图片缺失时仍会返回可生成的文字部分，但完整卡面、升级卡面和遗物图需要另行准备本地图片资产。

### 3. 配置 NapCat 并启动

让 NapCat 提供可连接的 OneBot WebSocket 地址，然后设置 Token。示例中的值均为占位符：

```powershell
$env:PYTHONPATH = "src"
$env:NAPCAT_TOKEN = "<your-napcat-token>"
$env:NAPCAT_WS_URL = "ws://127.0.0.1:3001"
python -m card_guess.qq
```

`NAPCAT_WS_URL` 未设置时默认使用 `ws://127.0.0.1:3001`。也可以显式运行：

```powershell
python -m card_guess.qq.runtime
```

旧入口 `python scripts\qq_ws_spike.py` 仍保留为薄兼容层，内部调用同一个 runtime。

runtime 会在 WebSocket 断开后退避重连，并使用单实例锁避免同一机器启动两个 Bot 导致重复回复。

## 已知限制

- 这不是完整游戏模拟器；不会模拟战斗、牌组、资源条件或所有事件状态。
- 只有部分复杂 Event 支持互动，完整多阶段连续互动目前仅覆盖少量经过验证的事件。
- 一些含动态变量、战斗或随机后续的 Event 只能展示现有资料，文本或后续结果可能不完整。
- 统计是本地历史快照，不是实时数据，也不是推荐或因果结论；不同指标的样本范围可能不同。
- STS2 Path Stats v2 尚未实现，不能查询完整路线或节点路径统计。
- runtime 能自动重连 NapCat，但目前没有独立的远程监控、进程守护或远程恢复系统。
- 卡牌/遗物目录和图片未随 Git 跟踪，部署者需要自行准备本地资产。

## 隐私与本地数据

Bot 在本地运行，查询使用本地目录、图片和统计快照。项目 runtime 的日志写入控制台和 `logs/bot.log`（UTF-8，单文件 5 MB，保留 3 份轮转），不记录 NapCat Token、Authorization header 或聊天正文。

QQ 与 NapCat 自身的数据处理和日志行为由各自的配置决定，不属于本项目 runtime 的隐私保证范围。

## Roadmap

继续补充经过验证的复杂 Event 流程与部署可靠性；STS2 Path Stats v2 仍处于未实现状态。
